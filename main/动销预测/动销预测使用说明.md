## 一、系统简介

动销预测系统是基于 OMS（订单管理系统）销售数据库构建的 **Python + PySide6** 桌面应用，能够对产品在不同渠道、品类、细分类、型号维度的动销数据进行多算法预测，并以表格形式直观展示结果。

### 核心功能

| 功能 | 说明 |
|------|------|
| 三大预测维度 | 渠道型号 / 渠道细分类 / 渠道大类 |
| 六种预测算法 | Naive / SMA(移动平均) / Median(中位数) / HW(指数平滑) / RF(随机森林) / Croston |
| 多条件筛选 | 按渠道、品类、细分类、型号关键词筛选 |
| 自动选优 | 对每个序列自动选择准确率最高的算法 |
| 结果导出 | 一键导出 CSV 文件 |

## 六、预测算法说明

### 6.1 算法列表

| 算法 | 名称 | 适用场景 | 特点 |
|------|------|----------|------|
| **RF** | 随机森林 | 有足够历史数据的稳定序列 | 特征工程强，捕捉非线性模式 |
| **HW** | Holt-Winters 指数平滑 | 有趋势的时间序列 | 自适应趋势，适合增长型数据 |
| **Croston** | Croston 方法 | **间歇性需求**（大量零值） | 专门为零星销售设计 |
| **SMA** | 简单移动平均 | 短期平稳序列 | 计算快，抗噪性好 |
| **Median** | 中位数法 | 异常值较多的序列 | 抗异常值能力强 |
| **Naive** | 朴素法 | 基线对比 | 用最后一期值作为预测，简单有效 |

### 6.2 自动选优策略

采用 **"特征分析 → 候选缩减 → 回溯验证"** 三阶段策略（详见 8.2）：

1. **序列特征提取**：计算稀疏度、趋势强度、变异系数、数据量
2. **preselect_predictors**：根据特征预选 2~4 个候选算法，排除不适配的算法
3. **backtest**：扩展窗口回溯，用 sMAPE 逐一评估，选最低者

这样每个序列都会自动匹配最优算法，实现**自适应预测**。

## 八、核心问题与设计思路

### 8.1 预测值兜底方案

**问题**：部分算法（如 RF、HW）对数据长度敏感，序列过短时可能输出极端值甚至超出 int32 范围，导致回写数据库时溢出。

**兜底策略（多层防御）**：

| 层级 | 机制 | 说明 |
|------|------|------|
| **预测前拦截** | `数据状态` 评估 | 历史 < 3 个月或全零 → 标记「严重不足」，直接跳过预测，使用零值 |
| **预测中兜底** | try/except + 零值 fallback | 算法 fit_predict 异常时返回 `np.zeros()` |
| **预测后裁剪** | 值域裁剪 | 预测值限定在 `[0, max(历史最大值×3, 1e6)]`，防止极端异常值 |
| **准确率空标** | 数据不足不标准确率 | 数据不足/严重不足时 `best_acc = None`，表格显示「数据不足」而非低分 |
| **序列预检** | preselect_predictors | 稀疏度 > 50% 禁用 RF；趋势强则禁用 Naive/Median，从源头减少不适配算法 |

> **核心思路**：不信任任何单一算法的输出，每一层都做防御。预测失败不可怕，输出一个可控的默认值（如 0 或最近一期值）远比输出一个溢出 int32 的异常值安全。

### 8.2 序列特征分析与算法自动选择

**问题**：10+ 种算法各有适用场景，如何为每个序列自动找到最优算法？

**思路：先分类，再回溯验证**。

#### 第一步：序列特征提取

对每个预测对象计算以下统计指标：

| 指标 | 计算方式 | 意义 |
|------|----------|------|
| **稀疏度** | 零值占比 | 判断是否为间歇性需求（→ Croston） |
| **趋势强度** | 尾部均值 vs 头部均值的相对差 | 判断增长/下降趋势（→ HW/RF） |
| **变异系数 CV** | std / mean | 判断稳定性（→ SMA/Median） |
| **数据量** | 有效月数 / 非零值数 | 判断是否适用复杂模型 |
| **连续性** | 近 3/6/12 月零值间隔 | 判断近期活跃度 |

#### 第二步：特征→算法映射（preselect_predictors）

```
稀疏度 > 50%   →  Croston / Naive / Median（禁用 RF）
趋势强度 > 0.5 →  HW / RF / SMA（禁用 Naive / Median）
CV < 0.3       →  SMA / Median / Naive（禁用复杂模型）
```

#### 第三步：回溯验证（backtest）最终定案

预选出的候选算法，通过 **扩展窗口 + sMAPE** 逐一评分，选出 sMAPE 最低者。

#### 扩展方案：聚类分析

将特征向量（sparsity, trend_strength, cv, n_points, n_nonzero）作为聚类的输入参数：

1. 对所有序列计算特征
2. K-Means 聚类（k=4~6），形成「高稀疏」「强趋势」「稳定型」「短序列」等类别
3. 每种类别提前绑定一组算法（如聚类1→Croston优先，聚类2→HW优先）
4. 新序列先分类，再在该类绑定的算法集内回溯选优

> 这种「先聚类定候选、再回测选最优」的两阶段策略，比全量回溯验证更高效。

### 8.3 缺失数据补全策略

**问题**：数据生产中缺失不可避免，如何合理补全？

| 策略 | 适用场景 | 方法 |
|------|----------|------|
| **零填充**（当前方案） | 无销售即缺行 | pivot_table fill_value=0，表示该月无动销 |
| **线性插值** | 偶发缺失（中间断点） | `series.interpolate('linear')` 平滑过渡 |
| **季节插值** | 年周期明显 | 按同比月份均值补：缺失的3月 = 历史各年3月均值 |
| **季波峰/波谷插值** | 季度特征强 | 每季度 max/min/mean 三点形成轮廓，插值缺失点 |
| **春节滞销处理** | 1-2 月年周期低谷 | 识别春节月份，使用春节调整因子（如 ×0.5） |
| **前值填充** | 短期稳定型 | ffill（用前一月值），适用于稳定序列 |

> **关键原则**：插值只用于「模型训练前的数据准备」，不用于准确率计算——准确率必须基于原始数据（含缺失），否则会高估模型能力（见 8.5）。

### 8.4 回测评价机制

**问题**：如何客观评价预测准确率？

**方案：扩展窗口回测（ Expanding Window Backtesting ）**

```
已知序列：[10, 20, 15, 30, 25, 35, 40, 50]  （8个月）
                         ↑ 划分线
训练集：[10, 20, 15, 30, 25]  （前5个月）
测试集：[35, 40, 50]            （后3个月）

预测：用前5个月拟合模型 → 预测后3个月 → 与真实值比较
```

**评价指标：sMAPE（对称平均绝对百分比误差）**

$$sMAPE = \frac{100\%}{n} \sum_{i=1}^{n} \frac{|A_i - F_i|}{(|A_i| + |F_i|) / 2}$$

- 值域 [0, 200]，越低越好
- 对零值和大值均有良好对称性
- 最终展示：`准确率 = max(0, 100 - sMAPE)`，以百分比形式输出

**扩展窗口**：每次保留最后 2~4 期做测试，不是固定切分，而是根据不同序列的数据量自适应调整测试窗口大小。

### 8.5 空值处理策略与客户反馈应对

**核心原则**：

> **空值 = 数据缺失（甲方数据问题），不用于准确率计算，但需要先插值再预测。**

#### 为什么不能轻易补充原始数据？

| 场景 | 错误做法 | 正确做法 |
|------|----------|----------|
| 缺失值 | 直接填均值/中位数，计算准确率时计入 | 插值后预测，计算准确率时排除缺失对应的真实值，标注「数据缺失」 |
| 全零序列 | 强行用算法拟合 | 标记数据不足，跳过预测，零值输出 |
| 异常值 | 直接删除 | 标记，用中位数替换后预测，准确率不计入 |

**职责边界**：
- 数据质量 → 甲方责任
- 预测方法 → 我方责任
- 准确率低 ≠ 算法差，需要区分是**数据问题**还是**算法问题**

#### 客户反馈应对策略

**场景一**："准确率这么低，预测系统没用啊，你们的算法不行。"

> **应对**：准确率低的序列中，有 X% 是因为历史数据不足 6 个月，Y% 是因为零值占比超过 50%。这些序列的数据状态已在报告中标注为「不足」或「严重不足」。对于数据充足的序列，平均准确率为 Z%。

**场景二**："我们数据就是这样的，那准确率低为什么不早说数据不行？"

> **应对**：这是合同前的评估盲区——先签合同才能拿到数据观察权。建议在合同中增加「数据质量评估」前置条款：签约后 5 个工作日内完成数据质量评估，若关键维度数据充足率 < 60%，则需双方确认是否继续。这样从流程上规避事后争议。

**场景三（延伸）**："能不能把数据补全了再预测？"

> **应对**：可以。我们会先对缺失值做插值填充，使模型能正常运行。但在准确率报告中，我们会明确标注「原始缺失值不参与误差计算」，这样既保证了预测可行性，又不会因数据问题拉低我方的准确率指标。

**应对落地方案**——在输出报告中增加三个列：

| 列名 | 含义 |
|------|------|
| 数据状态 | 充足 / 一般 / 不足 / 严重不足 |
| 缺失率 | 该序列中零值或缺失占比 |
| 预测可靠性 | 基于数据状态的建议（可信 / 参考 / 不可信） |

> **一句话总结**：数据质量越高，算法越能体现价值。数据不好时，宁可标出「不可信」也不要硬凑一个看似体面的数字。

## 九、常见问题

**Q1：为什么某些序列的准确率较低？**
A：查看「数据状态」列——若为「不足」或「严重不足」，说明历史数据太少或零值过多，不是算法问题。数据充足的序列平均准确率可作为参考。

**Q2：预测需要多久？**
A：取决于数据量和维度。渠道大类最快（几十个序列），渠道型号最慢（数千个序列）。一般 5~60 秒。

**Q3：可以自定义算法吗？**
A：可以。继承 `BasePredictor` 类并实现 `fit_predict()` 方法，加入 `PREDICTORS` 列表即可。

**Q4：如何提高预测准确率？**
A：① 缩小筛选范围减少噪音；② 增加历史数据量；③ 数据不足的序列优先用 Croston 或 Median。

**Q5：导出的 CSV 可以用 Excel 打开吗？**
A：可以。CSV 为 UTF-8 with BOM 编码，Excel 直接打开。

**Q6：数据有缺失怎么办？**
A：详见 8.3。插值后预测，但准确率计算时排除缺失对应的真实值——数据质量不是算法问题。
